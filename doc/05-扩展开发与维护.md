## 架构与职责

```text
Wrapper / Request
  → RouteSession 执行 before，按最终 Request 选组并加入事务参与者
  → 具体 Session 构造上下文、调用 ParseManager
  → ParseResult 携带 SQL 或 SDK 请求
  → Session 执行并转换为 IDataBuffer
  → CoderManager 解码为模型
  → EntityProxyService 按需要增强关联对象
  → RouteSession 执行 after 并返回最终结果
```

| 层 | 职责 | 不应承担 |
| --- | --- | --- |
| Wrapper/Request | 查询或写入意图 | 识别具体数据库语法 |
| ParseManager/IParse | 节点注册、生成 SQL/SDK 请求 | 借连接或提交事务 |
| CoderManager/IDataBuffer | Java 与后端值转换 | 选库和连接池治理 |
| Session | 执行、参数绑定、读取、本数据源连接资源 | 执行过滤器、独立开启业务事务、反向调用事务管理器或复制没有差异的 CRUD 解析器 |
| SessionFactory | 创建 Session，并完整初始化缓存、编码器、解析器、代理服务、日志、配置和 group | 默认承担路由注册或建表 |
| RouteSession | 唯一业务事务和过滤器增强入口、会话选择、登记参与者 | 持有自己的事务上下文、翻译方言或实现 XA |
| IFilterManager/SimpFilterManager | 注册、排序、匹配、顺序执行过滤器 | 选择数据源、执行 SQL 或管理事务 |
| TransactionListenerManager | 统一业务上下文、嵌套深度、代理写回、资源完成与回调 | 直接操作 JDBC Connection 或实现 XA |
| LoadBalance | 默认组、同组节点权重及健康快照 | 数据源 URL 校验或事务一致性 |
| EntityProxyService/EntityProxyFactory | 关联加载、同步代理生成与脏字段记录 | 再维护一套事务 ThreadLocal 或自行提交连接 |
| cache-core | 缓存 SPI、`CacheClient`、Key 值对象、TTL 与 namespace/partition 模型 | 解析 INode、Wrapper 或数据库表注解 |
| core/cache | ORM 查询 Key 构造、表依赖解析和写后失效决策 | 实现 Caffeine、Ehcache 或 Redis 存储 |

业务 CRUD 必须经过 RouteSession，Model Wrapper、Request 便利方法和事务切面均接入这一入口。具体 Session 是执行器和资源参与者，不作为独立业务事务入口；建表 SQL 预览、启动 Schema 初始化和解析器专项用例仍可以直接使用其底层能力。

### 过滤器边界

查询与写入共用 PreparedRequest，携带最终 Request、Session 和真实入栈次数，不再用 Request.sessionChange 猜测清理次数。before 的新请求必须被采用，继承调用者路由/执行选项，同时检查 group 和 cluster。动态表名改写在 SQL 解析和缓存之前完成，fromClass 不必改变。具体 Session 的 `setFilterManager/getFilterManager` 已移除，第三方工厂也应停止配置这项依赖。

after 的新结果必须返回给调用方，按列表、Page、Integer 校验类型；IRequestFilter 对分页列表分发 selectAfter，仅更换列表时才创建保留 total/extra 的新 Page。缓存命中也执行 after，Session 内部分页调用不重复增强。延迟写 before 在入队前执行，after 在后台实际执行后触发，普通后台后处理异常不重试已执行 Node。完整规则见第二专题的[过滤器](02-CRUD与统计分析.md#请求与结果增强过滤器)。

SimpFilterManager 注册时复制并稳定排序，Comparator.comparingInt 避免 order 相减溢出；发布 volatile 数组快照，before/after 各自读取快照，无读锁、不创建迭代器。test 每次执行，不缓存依赖当前请求或用户的匹配结果。注册可与请求并发，但过滤器本身须无请求级共享状态。回归用例统一放在 admin/src/test/java，当前只做静态核对，未执行编译或测试。

### 事务提交成功扩展点

`TransactionListener` 保留 `startTransaction()`、`commitTransaction()`、`rollbackTransaction()`、`afterCompletion()`，`afterCommit()` 使用默认空实现保持接口兼容。监听器只接收最外层的生命周期通知：嵌套开启、提交不重复调用监听器，内层回滚只标记共享事务 rollback-only，直到最外层结束再通知。扩展监听器无需自行维护嵌套栈。`TransactionListenerManager.afterCommit()` 通知所有固定监听器，一处失败不会跳过后续监听器。

`core.transaction.TransactionContext` 只由 `TransactionListenerManager` 的当前线程存储创建、释放，不再使用 Session 私有的 TransactionScope 或上下文继承体系。RouteSession 及其注解入口复用它，嵌套只增减 `depth`；选定节点、参与 Session、按 Provider 汇总的缓存失效范围、`afterCommitTasks` 和代理 `ProxyChanges` 都在同一个上下文中。第一次创建它的管理器负责本次监听生命周期，后续路由嵌套不重复通知。不同线程隔离；各 JDBC Session 的连接池仍单独持有，统一上下文不代表共用一个物理连接。已移除空转发层 BaseTransactionSession，业务事务转发直接位于 RouteSession，RegisterSession 只提供注册和选库钩子。

管理器最外层提交统一执行：固定监听器的提交前处理 → `ProxyChanges.flush()` → 各参与 Session 的资源提交 → 清理代理、解绑上下文并通知 `afterCompletion()` → 处理缓存失效 → 成功监听和业务回调。代理按来源组和实体类型分批生成部分更新，保留脏字段、主键和乐观锁逻辑；只迁移事务归属，不重写 CGLIB 或更新解析器。代理服务不再作为固定 TransactionListener Bean 重复注册，旧手动生命周期方法仅保留为弃用兼容入口。回滚丢弃脏记录和成功回调。提交资源出现异常时只做基本回滚和清理、向外报告异常，不实现断线确认、重试、补偿或分布式原子提交。

`TransactionUtil.afterCommit(Runnable)` 直接委托当前路由业务上下文的管理器，无业务事务直接报错，不提供独立 Session 或其他 Spring 事务管理器的回调兜底。业务 Runnable 保存在本次上下文，不放入全局 Listener 列表。`@Transactional` 使用 Spring 标准注解拦截器，经 `RouteTransactionManager` 接入 RouteSession，不另外注册拦截同一注解的切面。代理写回、固定提交前监听、连接提交和成功通知都由框架管理器按顺序执行；不注册 Spring 同步回调，不维护 `springStatus`，已经解绑的旧上下文不会清理后来新事务的状态。

清理异常不会跳过已成功提交事务的通知，某个监听器或业务回调失败也不会跳过后续任务；最终传播首个异常，其他异常合并为 suppressed，不重新进入已提交事务的回滚分支。所有显式开启必须配对结束；普通 CRUD 只登记资源，不增加深度。该能力不实现 REQUIRES_NEW、NESTED 或跨线程事务传播。业务用法见第二专题的[提交成功回调](02-CRUD与统计分析.md#提交成功回调)。

数据源实现的 `startTransaction/commitTransaction/rollbackTransaction` 仅负责本 Session 的连接资源；管理器首次登记时调用 start，最外层结束时调用 commit 或 rollback，不能反向调用管理器。`isOpenTransaction/setRollbackOnly/isRollbackOnly` 同样只读写本地资源状态。已删除重复的 `*TransactionResource` 桥接接口，不需要再实现两套同义方法。AbstractSession 的执行包装只记录日志、传播异常并标记自身资源失败，不自动开启或提交业务事务；JDBC 资源缺失的写操作明确报错，不能退化为自动提交。非 JDBC 默认只记录参与和回滚标记，保证事务内绕过缓存，不代表 ES/MongoDB 已具备服务端物理事务或回滚能力。

事务上下文、代理状态和独立连接管理的改动仅做静态核对，未执行编译、测试或打包。JDBC 资源登记仍延迟到真正执行 SQL 时才借连接，批处理连接在原线程初始化后再交给工作线程。

事务诊断开关为 `yulinlin.data.transaction-log`，默认关闭，由 core 自动配置传给 `TransactionListenerManager`。每个 `TransactionContext` 在创建时固定自己的 `TransactionLog` 和进程内事务 ID；JDBC 连接池只捕获这一日志对象用于关联 ID，不通过它开启或协调业务事务。异步连接日志复用捕获的对象，SQL 执行前在所属线程将 ID 写入本次 `ParseResult`，包括并行解析后的所有批次，不读取工作线程的业务 ThreadLocal。关闭时仍保留 ID，但不读取事务诊断时钟、不输出生命周期日志；不存在框架事务时使用 `none`。日志不能改变提交/回滚决策；框架资源方法返回与 JDBC 物理 commit 分别记录，不把上下文清理、SQL 执行成功或 afterCommit 回调异常误报为数据库提交/回滚结果。该诊断改动仅做静态阅读核对，未编译、运行测试或打包。

`ConnectionPool` 统一使用目标 `DataSource.getConnection()`，不调用 `DataSourceUtils`，不检查或复用 Spring holder。`TransactionAwareDataSourceProxy` 解包后再借连接，避免自管连接被代理重新导向线程绑定连接。开启时记录原始 autoCommit 并设为 false；结束时等待批处理归还连接，逐个提交/回滚，完成无异常时恢复原状态，最终直接 close。资源异常仍向外传播，不靠日志掩盖。旧 `ConnectionUtil.getSpringConnection/releaseSpringConnection` 仅保留弃用委托，实际使用独立连接；`isSpringManaged()` 兼容方法固定返回 false。

`jdbc.transaction.RouteTransactionManager` 只实现 Spring `PlatformTransactionManager` 协议，不继承 `AbstractPlatformTransactionManager`，不建立第二份资源上下文。每个注解调用的状态只保存原框架上下文身份和嵌套深度，用于防止跨线程、重复结束或手动事务未配对。Spring 标准拦截器负责注解解析和异常回滚规则，框架负责物理生命周期。仅接受 REQUIRED、默认隔离/超时和 readOnly=false，其他语义在业务执行前拒绝。DataJdbcApplication 提前注册 `@Primary` 的 `yulinlinTransactionManager`，使 Boot 默认 JDBC 事务管理器退让；通过 ObjectProvider 延迟获取 RouteSession，避免基础设施创建时循环依赖。原生 JdbcTemplate/MyBatis/JPA、其他事务管理器与本框架事务独立；不提供 Spring 同步事件或 JPA/JTA/XA 桥接。

源码入口：core/session、core/loadbalan、core/proxy、core/parse、core/coder；jdbc/session 和 jdbc/sql。缓存公共协议位于 cache-core，ORM 相关解析仍位于 core/cache，三个 Provider 只依赖 cache-core。为保持已有业务源码兼容，cache-core 中的公开类型暂时继续使用 `com.yulinlin.data.core.cache` 包名；模块边界已经独立，不要求调用方修改 import。数据库语法放在 Parse，驱动读写差异放在 Session，不额外引入 SqlDialect 或 Session.sqlXXX 拼接层。

## 新增数据源流程

1. 明确 JDBC/非 JDBC，列出 CRUD、分页、JOIN、聚合、事务、并发和类型支持。
2. 新建独立模块，继承根 POM 并加入 modules；JDBC 依赖 jdbc + 驱动，非 JDBC 依赖 core + SDK。
3. 注册确有差异的 IParse；不支持的节点明确拒绝，不静默忽略。
4. 优先复用 JdbcSession；只有执行/驱动差异才增加 Session 子类。
5. 核对 Java 编码、参数绑定、数据库类型及读取的完整往返。
6. 模块自行声明工厂与 Session Bean，添加自动配置 imports。
7. 检查 group、事务、并发、资源所有权和释放路径；不能引入 Spring 绑定连接复用。
8. 补最小用法、能力限制与验收案例；执行验证须由当前任务授权。

没有差异就直接用公共注册项。不要依赖另一个数据库模块、复制空继承类或重复工具包来“兼容”。

## JDBC 接入示例

### 解析器注册

SqlParseManager 复用 CRUD/条件/JOIN/聚合；它不是天然兼容所有数据库的标准 SQL 层。默认 JSON 和分页带 MySQL 风格，日期/区间需要模块自己注册。

当前 PostgreSQL 的注册方式：

```java
package com.yulinlin.jdbc.postgresql;

import com.yulinlin.jdbc.postgresql.parse.NameParse;
import com.yulinlin.jdbc.postgresql.parse.PageParse;
import com.yulinlin.jdbc.postgresql.parse.group.DateParse;
import com.yulinlin.jdbc.postgresql.parse.group.IntervalParse;
import com.yulinlin.jdbc.postgresql.parse.base.MatchParse;
import com.yulinlin.jdbc.postgresql.parse.select.AsFieldParse;
import com.yulinlin.jdbc.postgresql.parse.statement.SqlSelectWrapperParse;
import com.yulinlin.jdbc.sql.SqlParseManager;

public class PostgresqlParseManager extends SqlParseManager {
    public PostgresqlParseManager(PostgresqlFullTextOptions options) {
        register(new MatchParse(options));
        register(new AsFieldParse(options));
        register(new SqlSelectWrapperParse());
    }

    @Override
    protected void init() {
        super.init();
        register(new NameParse());
        register(new PageParse());
        register(new DateParse());
        register(new IntervalParse());
    }
}
```

SimpParseManager 以 IParse.getNodeClass 注册，相同键后注册覆盖前者；普通分派按实际 Class 查找，不自动搜父类。NameParse 的元节点入口需沿用公共契约。

构造函数会调用可重写的 init，此时子类字段尚未初始化，不能依赖构造后才赋值的成员。注册表初始化后不再动态修改；同数据库语法可以共享，跨数据库用不同注册表。

解析器不保存当前 root/参数/别名/连接。SqlParamsContext 保存本次管理器、NameParse 和 SELECT 表达式，不引用 Session，不把临时别名写入共享模型映射。

公共 `MatchParse` 是包含式 LIKE 回退；PostgreSQL 覆盖为 `to_tsvector @@ websearch_to_tsquery`，Elasticsearch 覆盖为原生 MatchQuery。`highlight` 是 AsField 上的选择标记，普通 JDBC AsFieldParse 忽略它；PostgreSQL 同时覆盖 SelectWrapperParse 与 AsFieldParse：先解析 WHERE，将当前请求的全文 query 表达式保存在 SqlParamsContext 的 request-local attribute，再解析 SELECT 并生成 ts_headline。不要把这些表达式放进 ParseManager 单例字段，否则并发请求会串数据。

全文索引 DDL 与查询必须使用同一 index-config 和完全相同的 tsvector 表达式。`@JoinField(fullText=true)` 只由 PostgreSQL SchemaManager 消费，其他 SchemaManager 不应误建普通索引；pg_jieba 是服务器扩展，框架只检查配置是否存在，不负责安装共享库或执行提权操作。

### Session 的差异

PostgresqlSession 构造时设置 PostgresqlParseManager；InputStream 绑定 setBinaryStream，BOOLEAN/BIT 用 getBoolean + wasNull，其他流程继承 JdbcSession。

常用可重写签名：

```java
protected void bindParameter(PreparedStatement statement, int index, Object value)
        throws SQLException;
protected Object readColumn(ResultSet rows, String label, int jdbcType)
        throws SQLException;
protected void beforeExecute(BaseRequest<?> request);
```

这是签名说明，不是完整类。扩展需检查实际批处理和查询入口是否调用这些方法，不能只证明单独工具方法能生成字符串。

beforeExecute 声明在 AbstractSession，实际查询、count、group 和非空写入在事务内部调用；纯 SQL 解析和查询缓存命中不调用。它适合请求级执行钩子，不应用于建表：否则缓存命中、原始 SQL、DTO 和事务边界会让 Schema 行为难以预测。默认实现为空，不改变其他后端。

core 中的 SchemaEntityScanner 在自动配置创建 Session Bean 时递归扫描各模块 `schema-packages`。`autoSchema` 默认 false；扫描器只保留显式 `autoSchema=true` 的具体普通单表结构拥有者，并按不区分大小写的物理结构名检测冲突。两个完整实体拥有同一结构时立即阻止启动；DTO/统计投影保持默认值即可。CRUD 路径不再根据 BaseRequest.fromClass 执行 DDL。

SqliteSession、H2Session、MysqlSession 和 PostgresqlSession 分别接收扫描结果并在初始化阶段处理结构。H2Database 同时保留池化业务 DataSource 和未暴露为 Bean 的直连 schema DataSource；MySQL/PostgreSQL 使用主 DataSource 的独立启动连接；SQLite 使用内部单连接库。初始化完成后，业务事务只负责业务 SQL。SQLite 会话仍禁止多连接写入拆组。

EntitySession 统一声明 `createTableSql(Class<?>)` 与 `initializeSchema(Collection<Class<?>>)`。AbstractSession 为不管理结构的后端提供空实现；MySQL/PostgreSQL/H2/SQLite Session 返回并执行 DDL，ElasticsearchSession 返回索引 Mapping 预览并创建或校验索引。JDBC `initializeSchema` 持有连接与 Statement，通过 JdbcSession 的受保护执行函数逐条打印 `[group][schema]` 后执行。方言 SchemaManager 只描述、校验结构并请求 Session 执行 SQL，不再自行创建 Statement，因此自动初始化和外部预览使用同一组 DDL 生成函数。

通用配置分两层：core 的 `EntitySessionProperties` 提供 `log`、`mapUnderscoreToCamelCase`、`schemaMode`、`schemaPackages` 和公共 `highlight`（标签、片段数、片段分隔符），可被 JDBC、Elasticsearch、MongoDB 等后端继承；jdbc 的 `JdbcSessionProperties` 再增加 `parallelConnections` 与 `executeBatchSize`。数据库专属的分词器、摘要长度或 highlighter 类型留在具体模块。具体模块配置类才声明 `@ConfigurationProperties`，公共父类不绑定全局前缀。旧 `JdbcProperties` 仅是弃用兼容桥，新扩展不要继续引用。

JoinIndex 是 core 中的可重复类注解，只有 fields 和 unique。jdbc.schema.EntityIndexResolver 统一把结构拥有者上的 Java 属性解析成持久化列，生成 `idx_<table>_<columns>` 或 `uk_<table>_<columns>`；超长名称使用 63 字符上限和 SHA-256 前 8 位稳定后缀。MySQL/PostgreSQL/H2/SQLite SchemaManager 只负责各自的元数据读取、DDL 和兼容性校验，不复制命名规则。各模块均保留未声明的额外索引，不自动删除或改名。

JoinField 的 `textType`、`textLength` 和 `description` 先由 `jdbc.schema.TextColumnResolver` 做跨数据库校验，再由各 SchemaManager 转成方言 DDL。字符串主键缺省长度和上限都是 128；大文本禁止作为主键或自动索引。MySQL/PostgreSQL/H2 校验显式 VARCHAR 长度，SQLite 只校验类型 affinity，不能把 `VARCHAR(n)` 当成实际长度约束。description 会在 MySQL/PostgreSQL/H2 创建新表或补充新列时落库，但不会修改已有列的注释。

### 自动配置完整模板

mydb、MydbParseManager 和驱动前缀是待替换的占位名称：

```java
package com.yulinlin.jdbc.mydb;

import com.yulinlin.jdbc.DataJdbcApplication;
import com.yulinlin.jdbc.JdbcSessionProperties;
import com.yulinlin.jdbc.session.JdbcSession;
import com.yulinlin.jdbc.session.JdbcSessionFactory;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.boot.autoconfigure.AutoConfiguration;
import org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean;
import org.springframework.boot.autoconfigure.condition.ConditionalOnSingleCandidate;
import org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import javax.sql.DataSource;

@ConfigurationProperties("yulinlin.mydb")
class MydbProperties extends JdbcSessionProperties {
    // Add only settings unique to this database.
}

@AutoConfiguration(after = {DataSourceAutoConfiguration.class, DataJdbcApplication.class})
@EnableConfigurationProperties(MydbProperties.class)
public class MydbAutoConfiguration {
    @Bean("mydbSessionFactory")
    @ConditionalOnMissingBean(name = "mydbSessionFactory")
    public JdbcSessionFactory mydbSessionFactory(MydbProperties properties) {
        return new JdbcSessionFactory(new MydbParseManager(), "jdbc:mydb:", properties);
    }

    @Bean("mydbSession")
    @ConditionalOnMissingBean(name = {"mydbSession", "jdbcSession"})
    @ConditionalOnSingleCandidate(DataSource.class)
    public JdbcSession mydbSession(DataSource dataSource,
            @Qualifier("mydbSessionFactory") JdbcSessionFactory factory) {
        return factory.create(dataSource, "mydb");
    }
}
```

需要专用 Session 时使用 `new JdbcSessionFactory("jdbc:mydb:", MydbSession::new, properties)`，由 Session 构造安装解析器。公共的 log、log-params、max-param-length、slow-sql-threshold、map-underscore-to-camel-case、schema-mode、schema-packages、parallel-connections 与 execute-batch-size 由 MydbProperties 继承并绑定在 yulinlin.mydb 下；同类某个 Session 需要例外配置时使用三参数 create 重载。前缀和 supportsJdbcUrl 仅保留兼容信息，不做自动类型校验。

资源声明文件 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 写入：

```text
com.yulinlin.jdbc.mydb.MydbAutoConfiguration
```

仅添加 AutoConfiguration 类不能保证被发现。新模块声明自己在 Spring 数据源及公共 JDBC 配置之后，不让公共 jdbc 按模块名维护选择工厂的清单。

### 创建与注册

公共 DataJdbcApplication 只提供编码器、日志和 Spring 事务注解适配器。各数据库模块注册自己的 Properties 和工厂并创建会话；core 收集 EntitySession Bean 注册到 RouteSession。

容器管理的工厂在 create 返回前完成 Session 的依赖初始化；create 本身不注册路由，也不保证手动 new 工厂的注入依赖齐全。非 Bean 会话可以通过已注入的工厂创建，再显式 route.registerSession(session)。注册阶段只登记负载均衡节点，不再注入缓存或补齐其他组件，不在 Session Bean 创建时反向依赖 route。

`EntitySession` 只暴露执行与资源协议，不声明 `setQueryCache`。继承 AbstractSession 的实现由工厂调用具体类的初始化方法；缓存使用 `ObjectProvider<QueryCache>` 收集后交给 `QueryCaches.single(...)`，无实现时使用 NoOpQueryCache，多个实现时明确拒绝。工厂与 RouteSession 复用同一个缓存 Bean，分别负责查询缓存与写后失效，不在注册时互相覆盖。

多个模块都可能注入同一 @Primary DataSource。group 名不同不代表物理源已隔离；业务应显式绑定工厂、池和组，完整例子在 [第一专题](01-接入与数据源.md#多数据源注册)。

### 编解码

JdbcCoderManager 复用 core 的日期、枚举、数字，并扩展集合/Map/对象的 JSON 编解码。特殊类型要把编码值、驱动参数类型、目标列和读回格式一起验证，不能以“写入成功”推定完整兼容。

MapCoderManager.registerCoder 不自动移除旧同类型编码器或清理已缓存选择；不是运行时覆盖接口。IDataBuffer 按请求/结果创建，不使用可变单例共享数据。

## 非 JDBC 接入

实现 SessionFactory<Client> 创建并完整配置 Session。通常继承 AbstractSession，实现 executeUpdate、executeSelect、executeGroup、executeCount、字段名策略及 ping/shutdown，把结果转成 IDataBuffer。与 JDBC 一样，工厂必须初始化缓存、编码器、解析器、EntityProxyService、日志、配置和 group，不能依赖 RouteSession 注册时补齐；EntityProxyService 用于查询后的关联加载和代理增强，不能遗漏。

解析器根结果用 ParseResult 携带 SDK 请求；子节点返回后端需要的对象，不强行套 SQL。客户端地址和凭据来自配置，不硬编码 localhost，不引入 jdbc 只为加入路由。Elasticsearch 模块当前基于 Java Client 9.5.4，使用默认 Rest5Client；新代码不要重新引入已弃用的 Apache HttpClient 4 RestClientTransport。

EntitySession/TransactionSession 接口不提供后端事务能力。AbstractSession 的计数也不会替 SDK 开启真实事务；当前 MongoSession、ElasticsearchSession 的开始/提交/回滚是空实现，不能照抄后宣称支持回滚。

有真实事务时映射嵌套、rollback-only、提交/回滚和清理；不支持时要设计无事务路径及能力拒绝。直接把 startTransaction 改成抛异常会影响 AbstractSession 的自动 CRUD 包装，需联动处理。

supportsParallelWrites 默认 false。异步任务必须明确传递或隔离资源和事务上下文，不能把 CompletableFuture 包装视为自动继承主线程事务。

## 负载均衡与资源生命周期

AbstractLoadBalance 只有一个注册组时直接选组；多个组使用应用共享 Bean 的 setDefaultGroup 或 yulinlin.datasource.default-group，没有配置/组不存在时报错。RegisterSession 委托同一默认规则，不保留静态 master 或取首组策略。

注册/移除发布只读 copy-on-write 快照；RandomLoadBalance 健康快照绑定注册快照，旧 ping 不恢复已移除节点。标签过滤不因单节点绕过。0 权重不参与，负权重拒绝；long 总和、[0,total) 抽样避免整数溢出和首节点偏置。

非事务请求重新选节点，路由事务内保留组和 cluster 的节点绑定。heartbeat 当前是空钩子，本轮不恢复自动后台调度；ping 是显式健康刷新。底层 JdbcSession.ping 仍主要返回 true，不代表真实服务探测已实现。

只读快照保护集合访问，不提供在途事务的资源租约。运行中随意改 group/cluster、关闭共享客户端或卸载租户仍需业务协调。

DataSource、SDK、流、执行器都需明确所有者。外部共享资源不因单个 Session 关闭被误关；内部资源应有销毁入口。JdbcSession.shutdown 主要记日志，不是连接池通用关闭器；factory.create(DataSourceProperties, group) 创建的池仍需所有者关闭。SQLite 使用 SqliteDatabase、H2 使用 H2Database 管理内部池，都不暴露 DataSource Bean。

## 迁移与排障

| 症状或旧入口 | 处理 |
| --- | --- |
| NoSuchMethodError | 比对编译/运行时 lang、core、jdbc 来源和版本；不能只替换部分 JAR |
| import jdbc.names.SqlNode | 当前类型为 com.yulinlin.jdbc.session.SqlNode |
| 原 PostgreSQL 包内 MysqlParseManager/MysqlParseAutoConfig | 使用 PostgresqlParseManager/PostgresqlAutoConfiguration |
| 原 PG 工厂名 mysqlSessionFactory | 改为 postgresqlSessionFactory，真正 MySQL 名称不变 |
| 默认 jdbcSession / primary | 默认 Bean mysqlSession/postgresqlSession，组 mysql/postgresql；自定义兼容名仍可让默认创建退让 |
| 多组默认不明确 | 设置 datasource.default-group 或显式请求组；primary 不自动优先 |
| Raw ExecuteRequest 执行返回 null | 原工厂未设置 requestType；当前源码已设置为 update |
| 原始 SQL 参数绑定为 null | Map 键使用裸名，SQL 保留 #{name}；ExpressionNodeParse 当前已修正 |
| 私有反射访问失败 | 检查模块 opens 和支持模型，不用吞异常绕过 |
| PostgreSQL 提示 MySQL 函数 | 工厂错配或原始 SQL 未迁移 |
| Git push publickey 认证错误 | 是远端认证问题，不等同于本地 commit 失败；检查实际 SSH 客户端和密钥，不修改业务代码 |

以上迁移信息依据当前源码，不表示部署产物已同步。日期格式、字段命名、JSON、原生类型、库版本和代理行为在目标环境验证。
