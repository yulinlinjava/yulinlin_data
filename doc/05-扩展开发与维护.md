本文面向框架维护者与开发新模块的 AI。说明源码职责、接入新数据源、编解码与负载均衡扩展，以及迁移、验证和历史性能记录。业务用法以第一至第四专题及第六专题为准，不把内部实现替代用户配置示例。

## 架构与职责

```text
Wrapper / Request
  → RouteSession 选组并加入事务参与者
  → 具体 Session 构造上下文、调用 ParseManager
  → ParseResult 携带 SQL 或 SDK 请求
  → Session 执行并转换为 IDataBuffer
  → CoderManager 解码为模型
  → EntityProxyService 按需要增强关联对象
```

| 层 | 职责 | 不应承担 |
| --- | --- | --- |
| Wrapper/Request | 查询或写入意图 | 识别具体数据库语法 |
| ParseManager/IParse | 节点注册、生成 SQL/SDK 请求 | 借连接或提交事务 |
| CoderManager/IDataBuffer | Java 与后端值转换 | 选库和连接池治理 |
| Session | 执行、参数绑定、读取、事务与资源 | 复制没有差异的 CRUD 解析器 |
| SessionFactory | 创建并配置 Session、group 和公共组件 | 默认承担路由注册或建表 |
| RouteSession | 会话选择、本地事务参与者协调 | 翻译方言或实现 XA |
| LoadBalance | 默认组、同组节点权重及健康快照 | 数据源 URL 校验或事务一致性 |
| EntityProxyService | 关联加载、同步代理的监听与清理 | 任意对象自动持久化 |

配置好的 Session 可以直接执行 Request，不经过 RouteSession；Model Wrapper 便利入口与关联代理仍有路由依赖。

源码入口：core/session、core/loadbalan、core/proxy、core/parse、core/coder；jdbc/session 和 jdbc/sql。数据库语法放在 Parse，驱动读写差异放在 Session，不额外引入 SqlDialect 或 Session.sqlXXX 拼接层。

## 新增数据源流程

1. 明确 JDBC/非 JDBC，列出 CRUD、分页、JOIN、聚合、事务、并发和类型支持。
2. 新建独立模块，继承根 POM 并加入 modules；JDBC 依赖 jdbc + 驱动，非 JDBC 依赖 core + SDK。
3. 注册确有差异的 IParse；不支持的节点明确拒绝，不静默忽略。
4. 优先复用 JdbcSession；只有执行/驱动差异才增加 Session 子类。
5. 核对 Java 编码、参数绑定、数据库类型及读取的完整往返。
6. 模块自行声明工厂与 Session Bean，添加自动配置 imports。
7. 检查 group、事务、并发、资源所有权和 Spring 绑定连接。
8. 补最小用法、能力限制与验收案例；执行验证须由当前任务授权。

没有差异就直接用公共注册项。不要依赖另一个数据库模块、复制空继承类或重复工具包来“兼容”。

## JDBC 接入示例

### 解析器注册

SqlParseManager 复用 CRUD/条件/JOIN/聚合；它不是天然兼容所有数据库的标准 SQL 层。默认 JSON 和分页带 MySQL 风格，日期/区间需要模块自己注册。

当前 PostgreSQL 的注册方式：

```java
package com.yulinlin.jdbc.postgresql;

import com.yulinlin.jdbc.postgresql.parse.NameParse;
import com.yulinlin.jdbc.postgresql.parse.PageParse;
import com.yulinlin.jdbc.postgresql.parse.group.DateParse;
import com.yulinlin.jdbc.postgresql.parse.group.IntervalParse;
import com.yulinlin.jdbc.sql.SqlParseManager;

public class PostgresqlParseManager extends SqlParseManager {
    @Override
    protected void init() {
        super.init();
        register(new NameParse());
        register(new PageParse());
        register(new DateParse());
        register(new IntervalParse());
    }
}
```

SimpParseManager 以 IParse.getNodeClass 注册，相同键后注册覆盖前者；普通分派按实际 Class 查找，不自动搜父类。NameParse 的元节点入口需沿用公共契约。

构造函数会调用可重写的 init，此时子类字段尚未初始化，不能依赖构造后才赋值的成员。注册表初始化后不再动态修改；同数据库语法可以共享，跨数据库用不同注册表。

解析器不保存当前 root/参数/别名/连接。SqlParamsContext 保存本次管理器、NameParse 和 SELECT 表达式，不引用 Session，不把临时别名写入共享模型映射。

### Session 的差异

PostgresqlSession 构造时设置 PostgresqlParseManager；InputStream 绑定 setBinaryStream，BOOLEAN/BIT 用 getBoolean + wasNull，其他流程继承 JdbcSession。

常用可重写签名：

```java
protected void bindParameter(PreparedStatement statement, int index, Object value)
        throws SQLException;
protected Object readColumn(ResultSet rows, String label, int jdbcType)
        throws SQLException;
protected void beforeExecute(BaseRequest<?> request);
```

这是签名说明，不是完整类。扩展需检查实际批处理和查询入口是否调用这些方法，不能只证明单独工具方法能生成字符串。

beforeExecute 声明在 AbstractSession，实际查询、count、group 和非空写入在事务内部调用；纯 SQL 解析和查询缓存命中不调用。它适合请求级执行钩子，不应用于建表：否则缓存命中、原始 SQL、DTO 和事务边界会让 Schema 行为难以预测。默认实现为空，不改变其他后端。

SchemaEntityScanner 在自动配置创建 Session Bean 时递归扫描各模块 `schema-packages`。`autoSchema` 默认 false；扫描器只保留显式 `autoSchema=true` 的具体普通单表结构拥有者，并按不区分大小写的物理表名检测冲突。两个完整实体拥有同一表时立即阻止启动；DTO/统计投影保持默认值即可。CRUD 路径不再根据 BaseRequest.fromClass 执行 DDL。

SqliteSession、H2Session 和 MysqlSession 分别接收扫描结果并在初始化阶段处理结构。H2Database 同时保留池化业务 DataSource 和未暴露为 Bean 的直连 schema DataSource；MySQL 使用主 DataSource 的独立启动连接；SQLite 使用内部单连接库。初始化完成后，业务事务只负责业务 SQL。SQLite 会话仍禁止多连接写入拆组。

EntitySession 统一声明 `createTableSql(Class<?>)` 与 `initializeSchema(Collection<Class<?>>)`。AbstractSession 为没有关系型 DDL 的后端提供空实现；MySQL/H2/SQLite Session 覆盖它们。`createTableSql` 是无连接、无副作用的预览入口，返回建表、注释和索引语句；`initializeSchema` 持有连接与 Statement，通过 JdbcSession 的受保护执行函数逐条打印 `[group][schema]` 后执行。方言 SchemaManager 只描述、校验结构并请求 Session 执行 SQL，不再自行创建 Statement，因此自动初始化和外部预览使用同一组 DDL 生成函数。

JoinIndex 是 core 中的可重复类注解，只有 fields 和 unique。jdbc.schema.EntityIndexResolver 统一把结构拥有者上的 Java 属性解析成持久化列，生成 `idx_<table>_<columns>` 或 `uk_<table>_<columns>`；超长名称使用 63 字符上限和 SHA-256 前 8 位稳定后缀。MySQL/H2/SQLite SchemaManager 只负责各自的元数据读取、DDL 和兼容性校验，不复制命名规则。三者均保留未声明的额外索引，不自动删除或改名。

JoinField 的 `textType`、`textLength` 和 `description` 先由 `jdbc.schema.TextColumnResolver` 做跨数据库校验，再由各 SchemaManager 转成方言 DDL。字符串主键缺省长度和上限都是 128；大文本禁止作为主键或自动索引。MySQL/H2 校验显式 VARCHAR 长度，SQLite 只校验类型 affinity，不能把 `VARCHAR(n)` 当成实际长度约束。description 只在创建 MySQL/H2 新表时落库，不触发已有列迁移。

### 自动配置完整模板

mydb、MydbParseManager 和驱动前缀是待替换的占位名称：

```java
package com.yulinlin.jdbc.mydb;

import com.yulinlin.jdbc.DataJdbcApplication;
import com.yulinlin.jdbc.session.JdbcSession;
import com.yulinlin.jdbc.session.JdbcSessionFactory;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.boot.autoconfigure.AutoConfiguration;
import org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean;
import org.springframework.boot.autoconfigure.condition.ConditionalOnSingleCandidate;
import org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration;
import org.springframework.context.annotation.Bean;
import javax.sql.DataSource;

@AutoConfiguration(after = {DataSourceAutoConfiguration.class, DataJdbcApplication.class})
public class MydbAutoConfiguration {
    @Bean("mydbSessionFactory")
    @ConditionalOnMissingBean(name = "mydbSessionFactory")
    public JdbcSessionFactory mydbSessionFactory() {
        return new JdbcSessionFactory(new MydbParseManager(), "jdbc:mydb:");
    }

    @Bean("mydbSession")
    @ConditionalOnMissingBean(name = {"mydbSession", "jdbcSession"})
    @ConditionalOnSingleCandidate(DataSource.class)
    public JdbcSession mydbSession(DataSource dataSource,
            @Qualifier("mydbSessionFactory") JdbcSessionFactory factory) {
        return factory.create(dataSource, "mydb");
    }
}
```

需要专用 Session 时使用 `new JdbcSessionFactory("jdbc:mydb:", MydbSession::new)`，由 Session 构造安装解析器。前缀和 supportsJdbcUrl 仅保留兼容信息，不做自动类型校验。

资源声明文件 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 写入：

```text
com.yulinlin.jdbc.mydb.MydbAutoConfiguration
```

仅添加 AutoConfiguration 类不能保证被发现。新模块声明自己在 Spring 数据源及公共 JDBC 配置之后，不让公共 jdbc 按模块名维护选择工厂的清单。

### 创建与注册

公共 DataJdbcApplication 只提供属性、编码器、日志和事务切面。各数据库模块调用自己的工厂创建会话；core 收集 EntitySession Bean 注册到 RouteSession。

工厂 create 本身不注册，也不保证手动 new 工厂的注入依赖齐全。非 Bean 会话在基础设施完成后可显式 route.registerSession(session)，不在 Session Bean 创建时反向依赖 route。

多个模块都可能注入同一 @Primary DataSource。group 名不同不代表物理源已隔离；业务应显式绑定工厂、池和组，完整例子在 [第一专题](01-接入与数据源.md#多数据源注册)。

### 编解码

JdbcCoderManager 复用 core 的日期、枚举、数字，并扩展集合/Map/对象的 JSON 编解码。特殊类型要把编码值、驱动参数类型、目标列和读回格式一起验证，不能以“写入成功”推定完整兼容。

MapCoderManager.registerCoder 不自动移除旧同类型编码器或清理已缓存选择；不是运行时覆盖接口。IDataBuffer 按请求/结果创建，不使用可变单例共享数据。

## 非 JDBC 接入

实现 SessionFactory<Client> 创建并配置 Session。通常继承 AbstractSession，实现 executeUpdate、executeSelect、executeGroup、executeCount、字段名策略及 ping/shutdown，把结果转成 IDataBuffer。

解析器根结果用 ParseResult 携带 SDK 请求；子节点返回后端需要的对象，不强行套 SQL。客户端地址和凭据来自配置，不硬编码 localhost，不引入 jdbc 只为加入路由。

EntitySession/TransactionSession 接口不提供后端事务能力。AbstractSession 的计数也不会替 SDK 开启真实事务；当前 MongoSession、ElasticsearchSession 的开始/提交/回滚是空实现，不能照抄后宣称支持回滚。

有真实事务时映射嵌套、rollback-only、提交/回滚和清理；不支持时要设计无事务路径及能力拒绝。直接把 startTransaction 改成抛异常会影响 AbstractSession 的自动 CRUD 包装，需联动处理。

supportsParallelWrites 默认 false。异步任务必须明确传递或隔离资源和事务上下文，不能把 CompletableFuture 包装视为自动继承主线程事务。

## 负载均衡与资源生命周期

AbstractLoadBalance 只有一个注册组时直接选组；多个组使用应用共享 Bean 的 setDefaultGroup 或 yulinlin.datasource.default-group，没有配置/组不存在时报错。RegisterSession 委托同一默认规则，不保留静态 master 或取首组策略。

注册/移除发布只读 copy-on-write 快照；RandomLoadBalance 健康快照绑定注册快照，旧 ping 不恢复已移除节点。标签过滤不因单节点绕过。0 权重不参与，负权重拒绝；long 总和、[0,total) 抽样避免整数溢出和首节点偏置。

非事务请求重新选节点，路由事务内保留组和 cluster 的节点绑定。heartbeat 当前是空钩子，本轮不恢复自动后台调度；ping 是显式健康刷新。底层 JdbcSession.ping 仍主要返回 true，不代表真实服务探测已实现。

只读快照保护集合访问，不提供在途事务的资源租约。运行中随意改 group/cluster、关闭共享客户端或卸载租户仍需业务协调。

DataSource、SDK、流、执行器都需明确所有者。外部共享资源不因单个 Session 关闭被误关；内部资源应有销毁入口。JdbcSession.shutdown 主要记日志，不是连接池通用关闭器；factory.create(DataSourceProperties, group) 创建的池仍需所有者关闭。SQLite 使用 SqliteDatabase、H2 使用 H2Database 管理内部池，都不暴露 DataSource Bean。

## 迁移与排障

| 症状或旧入口 | 处理 |
| --- | --- |
| NoSuchMethodError | 比对编译/运行时 lang、core、jdbc 来源和版本；不能只替换部分 JAR |
| import jdbc.names.SqlNode | 当前类型为 com.yulinlin.jdbc.session.SqlNode |
| 原 PostgreSQL 包内 MysqlParseManager/MysqlParseAutoConfig | 使用 PostgresqlParseManager/PostgresqlAutoConfiguration |
| 原 PG 工厂名 mysqlSessionFactory | 改为 postgresqlSessionFactory，真正 MySQL 名称不变 |
| 默认 jdbcSession / primary | 默认 Bean mysqlSession/postgresqlSession，组 mysql/postgresql；自定义兼容名仍可让默认创建退让 |
| 多组默认不明确 | 设置 datasource.default-group 或显式请求组；primary 不自动优先 |
| Raw ExecuteRequest 执行返回 null | 原工厂未设置 requestType；当前源码已设置为 update |
| 原始 SQL 参数绑定为 null | Map 键使用裸名，SQL 保留 #{name}；ExpressionNodeParse 当前已修正 |
| 私有反射访问失败 | 检查模块 opens 和支持模型，不用吞异常绕过 |
| PostgreSQL 提示 MySQL 函数 | 工厂错配或原始 SQL 未迁移 |
| Git push publickey 认证错误 | 是远端认证问题，不等同于本地 commit 失败；检查实际 SSH 客户端和密钥，不修改业务代码 |

以上迁移信息依据当前源码，不表示部署产物已同步。日期格式、字段命名、JSON、原生类型、库版本和代理行为在目标环境验证。

### AI 使用约定

AI 先读第一专题的版本和模块选择，再按任务读所需章节；框架扩展再读本文。不能套用 MyBatis-Plus、JPA、Spring Data 的接口，不能凭方法名发明参数。

生成业务代码前提供表结构、模型基类、主键/where、会话 group 和事务边界。自定义 SQL 提供目标数据库；HTTP 提供接口样例而非真实密钥；复制任务提供引用关系及类型需求。未验证应明确说明，不把统计或性能结论超出样本外推。

## 历史克隆基准

以下从 2026-10-01 的本机报告迁移，是历史记录，不是本轮运行或当前所有对象的排名。
